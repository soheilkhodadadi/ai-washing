# Journal Replication Archive Policy

The AI Washing workstation has two legitimate share profiles. Confusing them creates avoidable risk.

## Coauthor Package

Audience: Thomas and Kuntara.

Purpose: let coauthors reproduce v4.3, inspect data provenance, understand limitations, and extend the analysis.

May include:

- `docs/coauthor_share_note.md`
- phase reports and coauthor runbooks
- extension playbooks and future-data notes
- private data-room instructions
- frozen v4.3 manuscript assets and generated evidence
- reports under `reports/referee/` generated by the audit layer

This profile can be conversational and redundant because it is meant to reduce collaboration friction.

## Journal Archive

Audience: journal data editor, referee, replication archive, or future public supplement.

Purpose: reproduce published results and document data restrictions without exposing private or informal materials.

Should include:

- root README and formal reproduction instructions
- code, scripts, tests, pinned dependencies, Docker/devcontainer files
- table-to-script and data-dependency manifests
- formal data availability and provenance statements
- pseudo/sample data where restricted data cannot be distributed
- frozen generated evidence and validation logs needed to compare outputs
- known limitations stated in formal language

Should exclude:

- coauthor share notes and OneDrive-specific notes
- phase-process reports, internal sprint logs, and rehearsal chatter
- local paths except formal provenance references where unavoidable
- private/licensed data unless journal policy and provider terms explicitly allow it
- credentials, tokens, `.env`, caches, generated runtime folders, and raw worktree artifacts

## Practical Rule

For coauthors, sharing the private GitHub repo plus OneDrive data room is appropriate.

For a journal, create a clean release archive from Git, then use `make package-surface-audit` to identify files that belong only in the coauthor profile. Do not zip the raw working directory because ignored local folders such as `.venv`, `.pytest_cache`, and generated `outputs/` may be present.

## Current Known Profile Split

Files currently appropriate for coauthor sharing but not for a cold journal archive include:

- `docs/coauthor_share_note.md`
- `docs/onedrive_data_room_checklist.md`
- `docs/phase*_*.md`
- `docs/current_state_and_roadmap.md`
- `docs/workstation_build_report.md`
- extension notes aimed at Kuntara's next research tests

These files are not mistakes in the coauthor workstation. They are simply not journal-archive material.
